# 素材の集約と、計画書から資料を編む仕組み

このリポジトリは、導線資料の**素材（物・場・操作UI）の正本**と、それを使って
**計画書から1ファイルのHTML資料を作る仕組み**を持つ。`kikaku.md` の3層をそのまま使う。

> **このリポジトリは非公開にする。** 校舎・プールの間取り（出入口・通路・死角）は防犯上の機微情報。
> 名簿・児童名は置かない（plan には組・係までしか書かない）。

## 置き場所

| 置き場 | 層 | 中身 |
|---|---|---|
| `objects/<物>/` | 物 | 机・用具などの絵（実寸 mm）。いまは desk-layout の複製（`objects/desk/ORIGIN.md`） |
| `spaces/<場>/space.json` | 場 | 区画・点・通路（実寸 m）。確認状態（仮／確認済）と出典を持つ |
| `core/` | 操作UI | 再生部 `flow.js`・見た目 `flow.css`・ひな形 `page.html` |
| `plans/<行事>/<場面>.json` | 中身 | 組・動き・場面のことば・合図・未確定事項 |
| `gas/<行事>/<場面>.html` | 生成物 | `tools/build.mjs` が作る。直接直さない |
| `tools/` | 道具 | `build.mjs`（生成と検査）・`check.mjs`（ブラウザで撮って確かめる）・`align.html`（間取り合わせ） |

既存の `gas/undokai/nyutai.html` `relay.html` は手書きのまま残す（模擬型のリレーはデータ化しない。`kikaku.md` 1節）。

## space.json

```jsonc
{
  "id": "pool", "title": "プール周り", "unit": "m",
  "status": "仮",                 // 仮 | 確認済。仮のあいだは資料に「仮の地図」と出る
  "sources": [...], "known": [...],  // 出典と、縮尺の根拠にした既知の長さ
  "size": [52, 30],
  "areas": [ { "id", "kind": "deck|water|room|box", "label", "sub?", "rect": [x,y,w,h], "lanes?", "zone?" } ],
  "points": { "line.1": [29, 18.8], ... },   // 組ごとの場所は <名前>.<組> にする
  "pointLabels": { "kutsu.12": "上ばき 1・2組" },
  "paths": [ ["a","b"], ["a","b",{ "oneway": true }], ["a","b",{ "minutes": 3 }] ],
  "marks": [ { "kind": "oneway", "from", "to", "label" } ],
  "views": [ { "label": "プール", "rect": [x,y,w,h] } ]   // 「どこを見る？」で寄せて映す範囲
}
```

- **壁で区切られていない場所に線を引かない。** 矩形を組み合わせて1つの場所（L字の廊下・ふくらみ）を作るときは、全部に同じ `"zone"` を付ける。輪郭だけが描かれ、つなぎ目に線は出ない。線＝壁、という読み方を崩さないため。
- **座標は実寸**（m）。所要時間は「道のり ÷ plan の speed」で出る。地図の外にある遠い場所（教室など）は通路に `minutes` を書く。
- `noThrough`：行き先にはなるが、通り抜けには使わない点（プールの中など）。
- 通路は点と点をつなぐ線。動きは最短の通路をたどるので、plan に道すじは書かない。
- 向き：図の上下左右は現場の目印で決め、`align.html` で写真に重ねて確かめてから `確認済` にする。

## 描き方の決まり（space.json → 図）

| 描く物 | 図での形 | space.json |
|---|---|---|
| 壁 | 実線。**線＝壁**。それ以外の意味で実線を使わない | 区画（areas）の辺。区画の中の壁は `walls`（縦か横の線分） |
| 壁のない ひとつながりの場所 | 外まわりだけ実線。矩形のつなぎ目に線を出さない | 矩形に同じ `zone` を付ける（L字の廊下、ふくらみ） |
| 床の上の目印（シャワー・見学場所） | 点線の枠。壁ではない | `kind: "mark"` |
| 扉 | 壁の切れ目＋両端に壁と直交する短い枠。開き戸・引き戸は描き分けない（動きが変わらないため） | `doors: [{ kind: "door", from, to, label?, fill }]` |
| 壁のない開口 | 枠のない切れ目 | `doors: [{ kind: "open", ... }]` |
| 階段 | 踏み段の平行線（0.6mごと。実寸0.3mでは詰まって読めない）＋上る向きの矢印。下りた先の階を書く。おどり場は無地 | `kind: "stairs", up: "left|right|up|down", to: "2Fへ"`。おどり場は `box`。全部同じ `zone`、折り返しの間の壁は `walls` |

- **すき間を作らない。** 隣り合う区画は辺を共有させる（同じ座標）。実際にすき間（屋外・物のある所）があるときは、それを1つの区画として描く。
  `build.mjs` が 0〜0.6m のすき間と、区画どうしの重なり（中に線が出る）を警告する。
- 扉の `from` `to` は区画の辺の上の2点（縦か横）。`fill` はその切れ目を塗る場所の種類（手前の区画の kind）。辺の上にない扉は `build.mjs` が警告する。

## 組の描き方
- 1組＝28〜36人のまとまり。plan の `groups[].n`（人数）と `color` で、8列の点のかたまり（0.45m間隔）として描く。上に組の名札を重ねる。
- 組の色：1組 赤 `#B3172B`／2組 黄 `#F2C037`／3組 青 `#1E5FCC`／4組 緑 `#46B97A`。学校の組の色（赤黄青緑）に合わせ、
  赤と緑が色覚で潰れないよう明るさを離した（color-coding の検査で全ペア合格。黄・緑は白地で薄いので点に濃い縁を付ける）。
  児童はひとりずつ描く（`n` 人。点の大きさ＝背の高さ、端が低い）。plan の手順 `{ at, form: "体操" }` はその場で隊形を変え、`{ at, layout: "入水", point, dur }` は plan の `layouts` の位置へ ひとりずつ移る（1列目＝プール側の列が先に動く）。
  線に沿う隊形：`{ path: [[中央側の始点],[角],…], side: "left|right"（進む向きに対して プール側）, gap, rowGap }`。角で直角に曲がる。
  `sync: "名前"` の手順は、全組の準備がそろった時刻（0.5分単位で切り上げ）に一斉に始まる。`signals` / `phases` も `sync` でその時刻に合わせられる。
  通路の `only: "exit"` は、手順に `via: "exit"` があるときだけ使う（退場専用の道）。
  `at` の無い手順は、前の動きのすぐ後に始まる（例：シャワーが終わった組から入水）。
  `layouts.入水`：水面を `rows` 列に等分し、各列を東西に等分。`place[組] = { rows: [1列目が入る列, 2列目が入る列], half: "left|right" }`。
  止まっている点に `space.forms` の隊形があれば、その隊形で描く（例：`{ rows: 2, along: "x", tall: "+x" }`＝プールの長辺に沿って2列、背の高い児童が +x 側）。点の大きさが背の高さ。移動中はかたまり。
  **色だけで組を伝えない**：名札（1組…）を必ず重ねる。見学は白い点＋点線。

## plan.json

```jsonc
{
  "key": "dai1ji",               // 配布URLの ?p= と保存の名前。いちど配ったら変えない
  "title", "subtitle", "space": "pool", "start": "8:25", "end": "10:36", "speed": 0.8,
  "groups": [ { "id": "1", "label": "1組", "script": "swim", "vars": { "c": 1, ... }, "style?": "watch" } ],
  "scripts": { "swim": [
      { "at": "8:25", "place": "room.{c}" },                       // 最初にいる所
      { "at": "8:35", "stagger": 1.5, "to": ["{kutsu}", "kotai.{c}"] },  // 出発時刻＋組の順×stagger分
      { "at": "9:00", "to": [ { "p": "shower", "wait": 1.5 }, "edge.{c}" ] } ] },
  "signals": [ { "at": "9:11", "text": "🔔 ..." } ],
  "phases": [ { "at", "say", "chips", "mine?", "warn?", "by": { "<組id>": { "say", "chips" } } } ],
  "open": [ "計画書で決まっていないこと" ]
}
```

- `{c}` などは groups の `vars` で置きかわる。`k` は同じ script の中の順番（0から）。
- `mine` は組を選んだ時だけ出る、その組だけの1行。`by` は役割ごとの言いかえ（見学など）。
- 先生だけが読む項目（実施判断・塩素・日誌・評価の基準など）は plan に入れない。

## 生成と検査

```bash
node tools/build.mjs plans/suiei/dai1ji.json   # 生成。引数なしで plans/ を全部
node tools/check.mjs gas/suiei/dai1ji.html <撮影先>   # Chromebook幅とスマホ横で撮る
```

`build.mjs` が止める（終了コード1）もの：存在しない点・行けない経路（一方通行の向き違い）・前の到着より早い出発。
知らせるだけのもの：**すれちがい**（2組が2m以内で向かい合って動く）・`open` の未確定事項。
すれちがいは計画の穴であることが多い。時間をずらすか通路を分けるかを先生に聞く。

## 再生の速さ
動いている間は実時間の約10倍（1分＝6秒）、だれも動いていない間は1分＝0.3秒で飛ばす（`core/flow.js`）。
